## 1. 产品概述

| 项 | 内容 |
|----|------|
| 名称 | 《一夜剧本》 |
| 题材 | 都市科幻 — 深夜都市 + AI 编剧/分叉叙事（meta 贴合岗位） |
| 平台 | 微信小游戏，纯 JS，Canvas 2D，无第三方引擎 |
| 时长 | 单局约 2～3 分钟 |
| 一句话 | 玩家在都市深夜经历 3 次抉择，走向 2 种结局的互动微剧。 |

### 1.1 成功标准（面试可演示）

- 微信开发者工具模拟器/真机预览：从开始到结局无阻断。
- 界面可读：背景、对话框、两个选项按钮清晰可点。
- README 说明 AIGC 管线（文案 + 配图），附生成过程截图或说明。
- 60 秒录屏：打开项目 → 玩到结局 → （可选）展示 README。

### 1.2 明确不做（YAGNI）

- 云开发 / 自建后端 / 游戏内实时大模型 API
- 存档、排行榜、支付、音效（时间允许可加，默认无）
- ComfyUI 实操（仅写在「后续规划」，不虚假声称已完成）
- 对象池、敌机、射击等官方飞机 Demo 逻辑

## 2. 剧情与世界观（都市科幻）

**设定：** 凌晨的都市写字楼/出租屋，主角是加班的创作者或策划。公司试用版「AI 编剧」能根据选择生成分支；玩家每一次点击都在「喂给模型」一条路径，最终看到 AI 给出的两种成片结局。

**基调：** 霓虹、雨夜、屏幕蓝光；文案短句，偏互动小说，不堆砌设定。

**节点规模：**

| 类型 | 数量 |
|------|------|
| 标题页 | 1 |
| 抉择场景 | 3（每场景 2 选项） |
| 结局 | 2 |
| 总字数 | 约 500～800 字 |

**结局判定（简化，降低今晚工作量）：**

- 仅根据**第 3 次选择**映射到 `ending_a` / `ending_b`。
- 前 2 次选择可改变中间场景文案或 `scene2a` / `scene2b` 分支文本，但不影响结局 ID（实现时可先写线性 3 场景，明晚再加中间变体）。

**示例抉择主题（实现时写入 `story.js`）：**

1. 是否把未完成的剧本交给 AI 续写？
2. 是否用 AI 生成「客户要的爽点」而牺牲原意？
3. 是否发布 AI 署名的成片？

## 3. 玩法与界面

### 3.1 状态机

```
title → playing (scene*) → ending → title
```

- `title`：显示游戏名、副标题「都市科幻 · 互动微剧」、按钮「开始」；可选小字「剧情由 AI 辅助编写」。
- `playing`：展示当前场景背景、旁白/对白、两个选项。
- `ending`：结局全文 + 按钮「再来一局」。

### 3.2 布局（竖屏 Canvas）

| 区域 | 占比（约） | 内容 |
|------|------------|------|
| 上/全屏 | 55～65% | 背景图 `drawImage` 或渐变兜底 |
| 中下 | 可选 | 角色立绘（一侧，可透明底） |
| 底部 | 25～30% | 半透明对话框 + 叙述文字 |
| 最底 | 固定高度 | 两个选项按钮（大触点） |

### 3.3 输入

- 仅处理 `touchstart` / 鼠标点击（开发者工具）。
- 命中检测：矩形区域与选项绑定，无拖拽。

## 4. 技术架构

### 4.1 工程基础

- 目录：现有 `d:\AAA\wexingame`（微信工具与 Cursor 同目录）。
- 保留：`game.json`、`project.config.json`、`project.private.config.json`。
- 替换：官方飞机大战逻辑；`game.js` 仍作为唯一入口。

### 4.2 目标文件结构

```
wexingame/
├── game.js                 # 入口：import Main from './js/main'; new Main();
├── game.json
├── project.config.json
├── images/                 # 沿用微信模板目录名（背景、立绘、按钮）
│   ├── bg_title.png
│   ├── bg_office.png
│   ├── bg_city.png
│   ├── char.png
│   └── btn.png             # 可选，也可用 Canvas 绘制圆角矩形
├── js/
│   ├── main.js             # 游戏状态机、主循环、场景调度
│   ├── story.js            # 剧情节点数据（唯一数据源）
│   ├── renderer.js         # Canvas 绘制
│   └── input.js            # 触摸命中与回调
├── README.md               # 运行说明 + AIGC 管线（面试主文档）
└── docs/
    └── aigc-pipeline.md    # 可选：管线详解、提示词示例
```

**不再引用（可删除或保留不 import）：**

`js/player/`、`js/npc/`、`js/base/`、`js/runtime/`、`js/databus.js`、原 `js/render.js`（若与新 `renderer.js` 冲突则重命名或合并）。

### 4.3 模块职责

| 模块 | 职责 | 依赖 |
|------|------|------|
| `story.js` | 节点定义、`getNode(id)`、起始 ID | 无 |
| `renderer.js` | 获取 canvas/context、适配屏幕、绘制各层 | `story` 当前节点 |
| `input.js` | 注册触摸、按钮区域、触发 `onChoice(index)` | 无 |
| `main.js` | 状态切换、加载节点、协调 renderer/input | 以上三者 |

### 4.4 剧情数据形状

```javascript
// story.js 中节点示例（字段名实现时保持一致）
{
  id: 'scene1',
  background: 'images/bg_office.png',
  portrait: 'images/char.png',       // 可选，空则跳过
  text: '凌晨两点，AI 编剧的试用窗口还亮着……',
  choices: [
    { label: '交给 AI 续写', next: 'scene2' },
    { label: '自己硬写结尾', next: 'scene2' },
  ],
}
// 结局节点：choices 为空或省略，含 endingKey: 'a' | 'b'
```

### 4.5 渲染与循环

- 使用 `wx.createCanvas()` / 全局 `canvas`（与官方模板一致）。
- `requestAnimationFrame` 每帧 `render()`；状态变化时重绘，无需物理更新。
- 资源：`wx.createImage()` 预加载；失败则 `renderer` 使用纯色渐变，不阻塞流程。

### 4.6 代码质量约束（实现阶段）

- 单函数认知复杂度目标 ≤ 15；多用卫语句提前返回。
- 配置与数据集中在 `story.js`，不散落在渲染逻辑中。
- 每个 `js/*.js` 文件头 Docstring + 关键函数说明（面试可读性）。
- 无硬编码 API Key、无外链脚本注入。

## 5. AIGC 策略（游戏外为主）

### 5.1 管线（文档与面试话术）

```
选题（都市科幻一夜）
  → 大模型生成分支剧本（JSON 结构）
  → 人工删改、写入 story.js
  → AI 绘图（背景 2～3 张 + 立绘 1 张）
  → 裁剪/重命名 → images/
  → 微信开发者工具预览 → 录屏
```

### 5.2 推荐工具（零基础友好）

| 步骤 | 工具示例 |
|------|----------|
| 剧本 | 通义千问 / DeepSeek / ChatGPT |
| 配图 | 即梦 / 豆包 / 通义万相 |
| 整理 | 手工命名；时间充裕可用简短 Python 重命名（非必须） |

### 5.3 游戏内呈现

- 标题或结局页一行：**「剧情由 AI 辅助编写」**（静态文案，非实时 API）。
- 不在面试中声称已上线 ComfyUI 批量流；可陈述为下一阶段优化。

### 5.4 提示词留存

在 `README.md` 或 `docs/aigc-pipeline.md` 中保存实际使用的提示词片段与 1～2 张生成截图路径说明，便于面试官追问。

## 8. 面试话术提纲

1. **为什么原生不用 Cocos：** 面试周期短，原生直接 Canvas + 触摸，资源当 PNG 即可，避免引擎资源管线问题。
2. **你负责什么：** 状态机、渲染、剧情数据整合、微信预览发布链路。
3. **AIGC 负责什么：** 剧本与视觉初稿；你策展、改 JSON、导入工程。
4. **与 JD 短剧的关系：** 《一夜剧本》是极简分支短剧；完整批量流用 ComfyUI/脚本为下一步。
