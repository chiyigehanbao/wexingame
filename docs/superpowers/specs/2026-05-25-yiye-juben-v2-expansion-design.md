# 《一夜剧本》v2 深度拓展 — 设计规格

**状态：** 待用户审阅 spec 文件（设计对话已确认 2026-05-25）  
**取代：** `2026-05-25-yiye-juben-design.md` 中的 v1 范围（3 抉择 + 2 结局 + AIGC 主线）  
**约束：** 本轮 **不使用 AIGC**（无游戏内 API、无 AI 配图流水线）；微信原生 Canvas 2D

---

## 1. 产品概述

| 项 | 内容 |
|----|------|
| 名称 | 《一夜剧本》 |
| 题材 | 都市科幻 · 深夜写字楼 · AI 编剧伦理 · **裁员** + **与过去的自己和解** |
| 平台 | 微信小游戏，纯 JS，Canvas 2D |
| 单局时长 | **约 15～20 分钟**（可分段，章节日志支持「今夜继续」感） |
| 一句话 | 裁员前夜，玩家在 **今夜答辩** 与 **三年前同一栋楼** 的蒙太奇之间抉择，用 QTE、邮件与压力系统完成一夜成片。 |

### 1.1 成功标准

- 微信开发者工具：从标题到 **4 主结局 + 2 隐藏结局** 至少各有一条可玩通路。
- 玩法：除旁白双选外，**QTE、邮件、倒计时** 在 P2 后各出现 ≥1 幕；P3 后含剪辑台/素材盘。
- 剧情：**无母亲/病房/消费死亡**；「我其实……」来自 **三年前自己的录影**。
- UI：肉眼可辨 **纸纹手稿（D）** + **HR/客户霓虹徽章（C）** + 雨夜背景；双时间线 **色温/章节前缀** 可区分。

### 1.2 明确不做（YAGNI）

- 游戏内实时大模型、ComfyUI、云开发、支付、排行榜
- 复杂 3D、物理引擎、多人
- 音频（可选后续）；对象池/射击等旧飞机 Demo 逻辑

## 2. 剧情与世界观

### 2.1 核心矛盾

- **外部：** 裁员名单/末次答辩/明早交付 — HR 红、客户金、时间压力。
- **内部：** 为 **三年前的自己** 补完一支三分钟片子；U 盘里是旧工程与未说完的「我其实……」。
- **工具：** 试用版「AI 编剧」把旧素材抛光成平台口号（如虚构的「我从不后悔」），与三年前真话冲突。

### 2.2 母题与道具

| 元素 | 说明 |
|------|------|
| 母题 | 你裁的是别人，还是三年前的自己？ |
| U 盘 | 旧工程、未发送粗剪 |
| 工牌 | 灰 — 身份/去留隐喻 |
| HR 邮件 | 裁员、答辩时间 |
| 客户 IM | 爽点、反转、九点前要成片 |
| 渲染队列 | QTE 卡点（99%） |

### 2.3 叙事结构（平行蒙太奇）：平行蒙太奇（用户选定 C）

章节在 **「今夜 · 时:分」** 与 **「三年前 · 节气/事件」** 之间交替；中段分别影响 `诚意_过去` / `诚意_今夜`；第 9 幕预览窗汇合；第 10～11 幕结局。

### 2.4 幕表（9～11 幕）

| 幕 | 时间线 | 章节意向 | 核心事件 | 主要 mode |
|----|--------|----------|----------|-----------|
| 1 | 今夜 | 空办公室的最后一格进度条 | 裁员传闻 + 发现 U 盘旧粗剪 | narrative |
| 2 | 三年前 | 入职季的第一次开机 | 拍「只给自己看的三分钟」 | narrative + 抉择 |
| 3 | 今夜 | 模型给出的完美句号 | 是否上传旧素材给 AI | narrative |
| 4 | 三年前 | 客户第一次改口 | 迎合爽点 / 硬留闷片 | narrative |
| 5 | 今夜 | 慢热稿纸与快的客户 | 客户施压 | mail + pressure |
| 6 | 三年前 | 署名栏第一次闪烁 | 联合创作署名选择 | narrative |
| 7 | 今夜 | 渲染队列里的 HR 抄送 | 渲染 QTE + HR 倒计时 | qte + pressure |
| 8 | 三年前 | 硬盘里未发送的那版 | 删/留关键旁白 | archive |
| 9 | 今夜 | 双时间线同一预览窗 | 同框预览 → 最终发布抉择 | edit 或 narrative |
| 10 | 汇合 | 走出旋转门 | 四主结局 | ending |
| 11 | 隐藏 | 章节日志「未发送」 | 条件解锁 | ending |

### 2.5 结局

| ID | 名称 | 条件概要 |
|----|------|----------|
| ending_a | 诚实署名 | 今夜诚实披露 AI/不偷换口号；诚意高 |
| ending_b | 流量隐瞒 | 不标注、爆款、空心 |
| ending_c | 双版本妥协 | 追加 AI 剪辑版救数据 |
| ending_d | 慢热坚守 | 坚持底片、数据惨淡但真话 |
| ending_secret_1 | 未发送的补全 | `诚意_过去` 高 + 今夜未采用 AI 口号 |
| ending_secret_2 | 亮着的工牌 | 全 AI 交差 + 讽刺留任感 |

结局由 `gameState.resolveEnding()` 根据 **flags + 数值阈值 + 关键节点 id** 判定，不单靠最后一次二选一。

### 2.6 文案源

- 全文案维护：`docs/story-copy-yiye-juben.md`（v2 重写，替换母亲线）
- 运行时数据：`js/story.js`（与文案同步）

## 3. 玩法与数值

### 3.1 隐性数值（UI 用徽章/细条暗示，不做 RPG 面板）

| 变量 | 范围 | 影响 |
|------|------|------|
| `诚意_过去` | 0～100 | 隐藏结局 1、结局文案变体 |
| `诚意_今夜` | 0～100 | 主结局倾向 |
| `压力` | 0～100 | QTE 窗口变短、超时恶化节点 |
| `ai_依赖` | 0～100 | AI 台词渗透、结局讽刺度 |

### 3.2 互动机制（实现优先级：5 → 4 → 3 → 1 → 2）

| 优先 | mode | 说明 | 典型幕 |
|------|------|------|--------|
| 1 | `qte` | 渲染卡点、电梯、感应灯节拍 | 7 |
| 2 | `mail` | HR/客户/三年前草稿；上滑展开，选回复倾向 | 5 |
| 3 | `pressure` | 答辩/交付倒计时；超时默认恶化 | 5、7 |
| 4 | `edit` | 3～5 句块时间轴，删留 AI 句 | 9 |
| 5 | `archive` | 镜头卡片勾选，删留三年前旁白 | 8 |

`narrative`：纸纹对话框 + 便签选项（2～3 项或「继续」）。

### 3.3 章节日志

- `wx.setStorageSync('yiye_chapter_log', [{ actId, title, timeline, ts }])`
- 标题页：有进度则显示「重温」；只读回放，不改数值。

### 3.4 节点数据形状

```javascript
{
  id: 'act7_now',
  timeline: 'now',           // 'now' | 'past'
  chapter: '今夜 · 05:56',
  title: '渲染队列里的 HR 抄送',
  mode: 'qte',
  text: '…',                   // narrative / 部分 mode 的说明
  modeParams: {
    beats: [{ at: 0.6, windowMs: 800 }],
    failNext: 'act7_fail',
    successNext: 'act8_past',
  },
  choices: [],                 // narrative / mail 使用
  onEnter: { flags: { sawHr: true } },
}
```

## 4. 界面与视觉（D + C）

### 4.1 美学方向

- **D 极简手稿：** 纸纹、便签按钮、墨字、翻页转场；QTE 提示像贴上的胶带便签。
- **C 官僚霓虹：** 雨夜都市保留；顶栏工牌灰、HR 红、客户金；进度/邮件像系统 UI。

### 4.2 Canvas 分层

| 层 | 模块 | 内容 |
|----|------|------|
| L0 | `atmosphere.js` | 雨、天际线；`past` 加琥珀遮罩，`now` 偏冷青 |
| L1 | `layers/paper.js` | 对话框、章节、便签选项 |
| L2 | `layers/chrome.js` | 工牌、邮件顶栏、霓虹进度 |
| L3 | `modes/*.js` | 当前交互模式 |

时间线切换：**~0.4s 纸纹翻页** + 色温闪变。

### 4.3 字体与色板（`theme.js`）

- 标题：宋体系 fallback（`Songti SC`, `STSong`, serif）
- 正文：略窄无衬线；时钟等宽
- 纸：`#f4efe6` / 墨 `#2a2520`
- 霓虹：HR `#e63946`、客户 `#ffc53d`、系统青 `#00f5d4`（与 v1 青磁衔接）

## 5. 技术架构

### 5.1 推荐方案

**α 模式机 + γ 视觉分层**（不引入第三方引擎）。

### 5.2 状态机

```text
title → playing(mode*) → ending → title
```

### 5.3 目录结构

```text
js/
├── main.js
├── story.js
├── gameState.js
├── theme.js
├── atmosphere.js
├── input.js
├── render.js
├── layers/
│   ├── paper.js
│   └── chrome.js
├── modes/
│   ├── narrative.js
│   ├── qte.js
│   ├── mail.js
│   ├── pressure.js
│   ├── edit.js
│   └── archive.js
└── renderer.js
```

### 5.4 模块职责

| 模块 | 职责 |
|------|------|
| `main.js` | 状态机、调度 mode、循环 |
| `story.js` | 节点图、`getNode`、起始 ID |
| `gameState.js` | 数值、flags、结局判定、日志写入 |
| `modes/*` | 各玩法绘制 + 命中 + 回调 |
| `layers/*` | L1/L2 静态 UI 组件 |
| `renderer.js` | 组合层、标题/结局壳 |
| `input.js` | 统一 `setHitRegions` |

### 5.5 质量约束

- 数据与配置集中在 `story.js` / `gameState.js`
- 单函数复杂度目标 ≤ 15；卫语句提前返回
- 无 API Key、无外链脚本

## 6. 交付分期

| 阶段 | 范围 | 验收 |
|------|------|------|
| **P1** | 新幕表文案；`timeline`；`narrative` + D+C 分层 UI；四主结局路由 | 模拟器任意主结局通关 |
